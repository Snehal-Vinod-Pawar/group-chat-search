# Search a Group Chat Properly

Semantic search over a group chat. You know a message exists — "we decided on Manali sometime" — but you don't remember the exact words, and searching "Manali" returns 200 hits. This project searches by **meaning**: you ask questions in natural language (including Hinglish) and it finds the actual messages, with the surrounding conversation for context.

## Features

- **Semantic search** — "when did we finalize the trip?" finds "chalo Manali fix hai" even though almost no words overlap
- **Attributed search** — "what did Priya say about the budget?" deterministically filters to Priya's messages
- **Temporal search** — "what did we discuss last month?" converts the phrase into a real date range and filters on it
- **Context expansion** — every result comes with 3 surrounding messages before/after, matched message clearly highlighted
- **Hinglish/code-mixed corpus** — 4,210 synthetic messages across 8 participants, 6 months

## Tech Stack

- **Frontend**: React + Vite
- **Backend**: Python + FastAPI
- **Database**: MongoDB (messages + embeddings in one collection)
- **Vector search**: MongoDB Vector Search
- **Embeddings**: `intfloat/multilingual-e5-small` (pretrained, 384-dim, no fine-tuning)

## How It Works

```
query -> parse (sender/date detection)
      -> query embedding ("query: " prefix, normalized)
      -> $vectorSearch on MongoDB with metadata pre-filters
      -> over-fetch + duplicate-text suppression
      -> context expansion (3 messages before/after, same thread)
      -> JSON response -> React UI
```

Messages are embedded once with the `"passage: "` prefix and stored in the same MongoDB documents as their text and metadata. The vector index is configured with `sender` and `timestamp` as filter fields so constraints are applied **during** retrieval, not after.

Duplicate short messages ("lol") tend to fill result slots, so the search over-fetches candidates (top_k x 10) and keeps only the best-scoring occurrence of each distinct text.

## Dataset

Fully synthetic, generated by `scripts/generate_dataset.py` with a fixed seed (reproducible, no real chat data):

- 4,210 messages, 8 participants (Priya, Rohan, Anjali, Karan, Meera, Vikram, Sneha, Amit)
- Jan-Jun 2024, with realistic bursts, quiet periods and weekend activity
- Hinglish, English, typos, emojis, one-word replies, forwarded-style messages
- Three long threads with concrete decisions:
  - **Manali trip** - destination debate, budget, dates, then "chalo Manali fix hai"
  - **House party** - date/venue/food, then "party confirm hai - March 16, Sneha's flat"
  - **Subscription sharing** - Netflix/Prime/Spotify, split cost finalized

## Run Locally

Requires Python 3.10+ and Node 18+.

**1. MongoDB Atlas**

Create a free cluster and a Vector Search index named `vector_index` on `group_chat_search.messages`:

```json
{
  "fields": [
    { "type": "vector", "path": "embedding", "numDimensions": 384, "similarity": "cosine" },
    { "type": "filter", "path": "sender" },
    { "type": "filter", "path": "timestamp" }
  ]
}
```

**2. Configure**

```bash
cp .env.example .env
# set MONGODB_URI to your Atlas connection string
```

**3. Generate data + embeddings** (one-time)

```bash
pip install -r requirements.txt
python scripts/generate_dataset.py     # generates + inserts 4,210 messages
python scripts/build_embeddings.py     # embeds all messages into MongoDB
```

**4. Start the app**

```bash
# backend
cd backend && python main.py           # http://localhost:8000

# frontend (new terminal)
cd frontend && npm install && npm run dev   # http://localhost:5173
```

**5. Benchmark** (optional)

```bash
python scripts/validate_benchmark.py   # sanity-checks the 40 test queries
python scripts/run_benchmark.py        # runs them against the live API
```

## Benchmark Results

40 test queries (`data/benchmark.json`), each with a marked correct message. 26 have **zero word overlap** between query and answer text - the queries that prove semantic retrieval. Measured against the live `/ask` API (no reranker):

| Scope | Top-1 | Top-3 | Top-5 | Top-10 |
|---|---|---|---|---|
| All 40 queries | 25.0% | 27.5% | 30.0% | 37.5% |
| Zero-overlap (26) | 19.2% | 23.1% | 26.9% | 34.6% |
| Semantic only (18) | 5.6% | 5.6% | 5.6% | 11.1% |
| Attributed (9) | 22.2% | 22.2% | 33.3% | 44.4% |
| Temporal (8) | 37.5% | 50.0% | 62.5% | 62.5% |
| Sender + temporal (5) | 80.0% | 80.0% | 80.0% | 80.0% |

Sender/date filters verified in 27/27 filter cases; context invariants pass 40/40.

## Known Limitation

Embedding-based retrieval on a noisy chat corpus is weaker than the filter-based paths. Without a sender or date constraint, generic short messages ("brb", "done") sit in the same narrow cosine-similarity band as real answers, so unfiltered semantic top-1 accuracy is low. Duplicate suppression helps (semantic top-10 doubled after it), but a proper fix would need a reranker or a cleaner corpus - both out of scope here. Queries with deterministic constraints work much better, which is the main lesson of this project: embeddings alone are not search.
